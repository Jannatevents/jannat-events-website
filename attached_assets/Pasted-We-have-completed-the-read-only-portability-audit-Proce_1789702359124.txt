The objective is to make the existing Express API portable to Railway
while preserving the existing database and Clerk configuration.

PHASE 1 — MAKE STARTUP SAFE

The audit found that API startup currently calls ensureSeeded() and
refreshPastEvents(), and refreshPastEvents runs every 60 seconds.

Add a production-safe environment switch:

DISABLE_STARTUP_WRITES=true

When this variable is true:

- Do not run ensureSeeded()
- Do not run refreshPastEvents() during startup
- Do not start the 60-second refresh interval

Normal API routes should continue functioning.

Do not change existing behavior when the variable is absent or false.

PHASE 2 — HEALTH ENDPOINT

Ensure the API has:

GET /api/healthz

It should return a simple successful JSON response without modifying
the database.

Preferably report basic server health without exposing secrets.

PHASE 3 — EXTERNAL NODE HOST COMPATIBILITY

Verify that the API:

- binds using process.env.PORT
- does not bind only to localhost
- can run using the existing production build command
- can start using the existing production start command
- requires no Replit-specific runtime except the existing storage system

Do not deploy it.

PHASE 4 — STORAGE ISOLATION

Do NOT migrate storage yet.

Identify exactly which API routes will fail outside Replit because
127.0.0.1:1106 will not exist.

Make sure failure of the storage integration does NOT prevent the
entire API server from starting.

Public event APIs, Clerk authentication, admin non-storage APIs,
settings APIs and /api/healthz should be able to operate even if
Replit App Storage is unavailable.

Do not replace storage with R2 yet.

PHASE 5 — DATABASE CONNECTION

Keep DATABASE_URL as an environment variable.

Do not inspect, print, replace or migrate its value.

Make the database connection compatible with an externally hosted
Node service using PostgreSQL SSL.

Do not disable SSL certificate verification globally.

If the existing connection string already controls SSL through its
parameters, preserve that behavior.

PHASE 6 — CORS

Prepare production CORS support for exactly:

https://jannat.events
https://www.jannat.events

using:

CORS_ORIGINS=https://jannat.events,https://www.jannat.events

Do not change the live frontend.

PHASE 7 — CLERK

Preserve the existing Clerk implementation and tenant.

Keep:

CLERK_PUBLISHABLE_KEY
CLERK_SECRET_KEY

as environment variables.

Do not expose their values.

Keep the /api/__clerk proxy operational on a standard Node host.
